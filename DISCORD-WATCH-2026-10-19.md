## Bug reports that matter for us
1. **Windows decimal separator corrupts saves** (Zorelmo, 18 Oct; Sam: "ugh, yep, this is bad"). 1.7 writes saves with the system decimal separator (comma on French/German/**Dutch** Windows) and reads dots back → pawns age centuries, need bars overflow. User (as Sanctus Scriptor) confirmed in the thread for Dutch. Workaround: Windows decimal separator = dot. Bridge plan: launcher option that runs the game with invariant globalization (`DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`) — to be tested with a boot test + save/load before it becomes default. Not fixed in any build up to 4982.
2. **Discord / overlays blow up VRAM** (several threads; Cookie: Discord installs a Vulkan layer for frame capping). VRAM climbs to 100 % even at the main menu, stable once Discord (or discord_clips) is closed; windowed mode also stabilises it. Relevant for the laptop: the user runs Discord. Sam calls it "exceptionally weird" — unfixed as of 19 Oct. Advice: test map runs with Discord closed; the bridge could list loaded Vulkan implicit layers in the run log (idea).
3. **Texture glitches on old/low-VRAM AMD and Intel iGPUs** ("Vanilla and DLC Graphic Glitch 1.7", "2012 pc", "1.7 Texture/Sprite bug on vanilla" on Intel UHD 620, Surface 4 Laptop 512 MB): sprites 4–5× too big / wrong items, pawns fine. Sam: "specific to a narrow range of hardware, 2012–2015 ish, about 5 people, hard to diagnose, at least a couple more working days". Partly resolved in 4980 for one user, not for others. **Not seen through the bridge** (our textures are correct since v13.35/13.37) — the bridge path differs from these drivers' native Vulkan.
4. **Vulkan validation errors inside Waylith** (TheKoala, GTX 1080 Ti, 4979): image layout mismatches in `GpuTextureService` (barrier says TRANSFER_SRC, actual TRANSFER_DST), WRITE-AFTER-WRITE hazards after `vkCmdCopyBufferToImage`, and draws sampling images still in UNDEFINED layout (map pass, pawn cache). Visible as huge red/green/magenta shapes on fire/geyser/projectile effects. No dev reply yet. For the bridge: D3D11 has no layouts, so the mismatch is harmless for us, but it explains why strict drivers glitch; keep the bridge tolerant of UNDEFINED-layout sampling (it is).
5. **GPU selection picks Microsoft "Dozen" (Vulkan-on-D3D12) over the native AMD driver** on one laptop (score 216172782113816574 vs 216172782113808383). Our bridge device is scored 288230376151748607 and wins over WARP; a native Intel Vulkan driver would score higher, which is what we want. 4980 added a manual GPU picker in settings.
6. **Alt-tab / fullscreen switching**: VK_ERROR_DEVICE_LOST on alt-tab (RX 580), freezes when changing display mode (iGPU user), multi-monitor "revert/keep" popup not showing (fix: monitor = automatic). 4979 fixed one rapid-alt-tab crash. Our launcher already runs windowed/borderless; keep it.
7. **Old drivers**: A10-8700P / R6 M340 with a 2016 OEM driver cannot start 1.7 at all until the driver is updated (BIOS-locked OEM driver). Same category as the HD 5500 (last Intel driver 2020) — the bridge is the answer there too; worth a line in the Ludeon report (minimum driver guidance).
8. **GTX 750 Ti (Maxwell 1) GPU hang** on Linux/Wayland 1–2 min after load; Sam links it to a VK_ERROR thread — engine-side.
9. Diagnostics worth copying: **Alt+`** in game writes `Crashes\diagnostics-<date>.txt` (5 MB, includes VRAM profiler); the frame profiler has a VRAM breakdown; `-EagerTextureUpload` launch argument (4982+).

## Logs pulled from #bug-reports (14 files, `package\DiscordLogs\`)
Analysed in the cloud (subagent pass). What they add to the thread text:
- **The "sprite glitch" threads are old AMD proprietary drivers, not VRAM.** R7 200 (driver 22.6.1, 2 GB), AMD iGPU (20.40.16, 512 MB), R7 M460 (20.10.35.02, 4 GB — the "UHD 620" laptop actually selected the AMD chip). The M460 log shows **no offload and no error** in a 12-minute session, so the oversized sprites happen without any memory pressure. Common denominator: AMD drivers 2020–2022 reporting Vulkan 1.2.1xx. The HD 5500 bridge is a different path and does not show this.
- **Waylith uses only memory heap 0.** On the Surface Laptop 4 (two 256 MiB device-local heaps) half the VRAM is never touched; 4078 VMA blocks for 275 MiB means almost every allocation is a dedicated block; RenderTargets alone (263 MiB) exceed heap 0 → `ErrorOutOfDeviceMemory` while re-uploading `Sand.psd` during a draw (`Texture2D.EnsureResident ← MeshBatchRenderer.ResolveTextureBinding`). Through our bridge the game sees one 8 GB heap, so none of this applies to the laptop.
- **Offload starts in the main menu** on 2 GB cards (`Device-local memory is over budget. 'ExpansionIcon_Biotech.png' … go to system memory`, `GameTexture 716 MiB (5397)` on 4977). 4982's lazy upload is the answer to that.
- **Driver-side OOM at submit** (2 GB AMD iGPU, driver 26.1.1): `vkQueueSubmit … VK_ERROR_OUT_OF_DEVICE_MEMORY` after 28 min with only 860 MiB of 1.9 GiB budget used — the budget numbers do not show it. Layers present on that PC: OBS, RTSS, EOS overlay, Rockstar (the game disables implicit layers at fallback stage 3; at stage 2 with the system loader they stay active — RX 580 log shows `GalaxyOverlayVkLayer`).
- **Minimize / focus regain is the fragile path**: Iris Xe `AccessViolationException` in `WindowRenderContext.CreateSwapchain ← Rebuild()` after `Focus regained after 31 s`; RX 580 `vkQueuePresentKHR … VK_ERROR_DEVICE_LOST` 30 s after `Rendering resumed after 113 s minimized`. The bridge recreates the swapchain on resize — keep that path robust; our launcher's windowed mode avoids the fullscreen variant.
- Every build requests API 1.2 and enables `VK_EXT_memory_budget` where available; `ComputeBuffer 40 MiB (5)` is allocated even with `-disable-compute-shaders`. The game also enumerates Microsoft "Dozen" (Vulkan-on-D3D12) adapters and scores them below native ICDs; our bridge adapter scores above WARP, which is what we need.
- Knobs seen in logs: `WAYLITH_VRAM_BUDGET_MB` (caps device-local VRAM; GTX 750 Ti user set 1024), `-disable-compute-shaders`, `-popupwindow`, `-EagerTextureUpload` (4982), `Alt+\`` diagnostics dump.
- Bridge to-do from this: consider reporting device API 1.2 instead of 1.0 (every working log is ≥1.2; the game lowers features for 1.0 devices and warns that 1.6-era mod shaders may break) — needs the 1.2 core features the bridge can honestly provide; check what `Effective Vulkan version 1.0.0` currently disables.

## Logs.zip (Vulkan validation thread, GTX 1080 Ti, 1.7.4979) — read 2026-10-19 evening
`RimWorld_VulkanValidation.txt` (763 lines) contains **one error type only: `VUID-vkCmdDraw-None-09600`** — 218 occurrences (109 unique). During `MapRenderFeature.MapMainPass` (73) and outside any debug region (the pawn-cache render), draws sample images whose current layout is **UNDEFINED** instead of SHADER_READ_ONLY_OPTIMAL. Five images, every mip level 0–9 of each, i.e. complete 10-level mip chains (≈512–1024 px textures) that were **bound and sampled before anything was ever uploaded or transitioned into them**. That is the lazy texture residency path (texture descriptor written, upload not yet done). The `VUID-VkImageMemoryBarrier-oldLayout-01197` / WRITE-AFTER-WRITE errors the reporter mentioned (atlas baking) are only in his screenshots, not in this file. The accompanying `Player.log` (3.4 MB, modded, 1080 Ti) shows the same 30 validation errors as `ERROR [Verse] [Validation]` lines and otherwise mod errors (Combat Extended, CAI 5000); no residency pressure on an 11 GB card.
Meaning for the bridge: D3D11 has no image layouts, so sampling a not-yet-uploaded texture just returns whatever the D3D11 texture holds (the bridge creates textures without initial data). On a strict native driver the same draw reads garbage → the glitches those reporters see. Nothing to fix on our side; it supports the Ludeon-report point that Waylith's residency bookkeeping races the first draw.
